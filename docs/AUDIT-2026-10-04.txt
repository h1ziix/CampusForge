CampusForge — полный технический аудит
Дата: 4 октября 2026 года. Проверена локальная рабочая копия.

Вывод: проект пока не готов к production. Есть полноценная основа backend,
но production build не проходит, несколько основных экранов показывают demo,
выявлены проблемы приватности, безопасности, загрузок и фоновой обработки.
Внешний production deployment в рамках этой проверки не исследовался.

2. Область и метод проверки

Монорепозиторий pnpm/Turborepo: Next.js web, отдельный BullMQ worker,
packages/db с Prisma/PostgreSQL, packages/shared с Zod, packages/ai с OpenAI.
Просмотрены web routes, actions, services, queries, auth/middleware,
130 исходных TS/TSX файлов в инвентаризации, UI, schema/migrations,
S3/Redis, worker jobs, AI provider/prompts, package scripts и инфраструктура.
Backend/security, worker/DB/AI и frontend проверялись параллельно.

Использованы frontend-senior, 21st-ui-review и Playwright для browser QA.
Автоматические предупреждения проверялись по исходникам; они не выдаются
за самостоятельные доказанные уязвимости.

Исходники приложения намеренно не редактировались. Восстановлены зависимости
через pnpm install --frozen-lockfile и затем --force, без обновления lockfile.
Созданы только отчёт, промпт и артефакты аудита. Реальные AI API calls,
регистрация аккаунтов, DB writes и мутации GitHub не выполнялись.

Проверки бизнес-логики использовали реальные функции с in-memory mocks.
Они доказывают конкретные ветки кода, но не заменяют интеграционный тест.

4. Наиболее важные проблемы

Приоритеты: P1 — блокирует выпуск/основной сценарий либо существенно влияет
на безопасность/приватность; P2 — значимый дефект, исправить перед production;
P3 — меньший риск или дефект качества. Срочная задача выпуска не означает,
что для всех security findings выполнен реальный exploit.

A01 [P1] Production build не проходит; pending мутаций неверно работает.
Файлы: apps/web/src/components/auth/sign-in-form.tsx:27;
sign-out-button.tsx:12; sign-up-form.tsx:23;
components/document/document-list.tsx:49;
components/flashcard/flashcard-set-list.tsx:41;
components/note/note-editor.tsx:50;
components/onboarding/onboarding-form.tsx:26;
components/task/create-task-dialog.tsx:52, edit-task-dialog.tsx:60;
components/workspace/create-workspace-dialog.tsx:45.
Причина: startTransition(async () => ...) при React/ReactDOM 18.3.1.
Сборка и tsc подтверждают 10 ошибок типов. Изолированный ReactDOM probe
также показал isPending=false и disabled=false при незавершённой операции;
повторный клик запустил вторую операцию. Это риск дубликатов/конкурирующих
изменений, даже если обойти проверку типов.
Исправление: явный pending state и обработка ошибок для async operations,
либо согласованная миграция React/Next. Не подавлять ошибки TypeScript.
Критерий: build/typecheck проходят, повторная отправка блокируется до ответа.

A02 [P1] Устаревшие runtime зависимости имеют актуальные security advisories.
Файл: apps/web/package.json:29–32; точные версии — pnpm-lock.yaml.
Установлены Next 14.2.35, next-auth 5.0.0-beta.25 и несколько @auth/core.
Next 14.2.35 входит в диапазон Windows-hosted RCE GHSA-p293-qw3h-jr36.
Primary advisory указывает исправления 15.5.24/16.3.3. Применимость именно
production зависит от ОС и режима сервера; текущая машина — Windows.
Также advisory GHSA-2xp9-vwfh-vxw4 относится к AVIF image optimization;
достижимость этой ветки и наличие необходимого sharp/libheif не доказаны.
Не все npm critical применимы: Auth.js fail-open GHSA-8fpg-xm3f-6cx3
описывает truthy auth object, но middleware здесь проверяет req.auth?.user,
а requireAuth — конкретный user.id. Email/OAuth advisories требуют providers,
которые сейчас не настроены. У primary Auth.js advisory severity low,
хотя npm audit помечает соответствующее срабатывание critical.
Исправление: перейти на поддерживаемую исправленную линию Next/Auth,
согласовать adapter/@auth/core, проверить миграцию и повторить audit.
Не использовать автоматический audit --fix --force без оценки совместимости.
Источники:
https://github.com/vercel/next.js/security/advisories/GHSA-p293-qw3h-jr36
https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4
https://github.com/nextauthjs/next-auth/security/advisories/GHSA-8fpg-xm3f-6cx3

A03 [P1] callbackUrl из query допускает выполнение JavaScript после входа.
Файлы: apps/web/src/components/auth/sign-in-form.tsx:19,35;
apps/web/src/server/actions/auth.ts:73–79.
Сценарий: внешняя ссылка sign-in с javascript: callbackUrl, затем успешный
вход. router.push получает query напрямую; redirect:false в signInAction
не защищает последующий клиентский переход. Поток до external navigation
проверен в установленном Next 14; официальная документация подтверждает
выполнение javascript: URL в контексте страницы. E2E с реальной сессией
не выполнялся. Возможны действия с правами вошедшего пользователя.
Исправление: allowlist внутренних маршрутов того же origin; отклонять
опасные protocol, // URL и backslash tricks. Для невалидного ввода /dashboard.
Источник: https://nextjs.org/docs/app/api-reference/functions/use-router

A04 [P1] История AI Assistant не изолирована по пользователю/workspace.
Файлы: apps/web/src/lib/assistant/storage.ts:11,44,73;
apps/web/src/components/assistant/assistant-app.tsx:58;
apps/web/src/components/auth/sign-out-button.tsx:12.
Один localStorage key campusforge:assistant:v1 используется всеми аккаунтами
на одном origin. Logout не очищает историю. Пользователь B на общем браузере
может увидеть чаты пользователя A; смена workspace также сохраняет историю.
Исправление: user/workspace scope хранения, политика logout и серверная
авторизация для синхронизации. Не переносить старый общий key всем пользователям.

A05 [P1] Основные AI сценарии в интерфейсе являются симуляцией.

Language/Temperature/System prompt/Memory/Notifications сохраняются,

либо явно маркировать весь этот режим как demo и отключить фиктивные настройки.
Критерий: изменение содержимого документа меняет результат; вывод переживает
перезагрузку и виден в других соответствующих разделах через DB.

A06 [P1] В новом AI чате поле ввода недоступно на части размеров экрана.

6. Backend, безопасность и сохранность данных

A15 [P2] AI deduplication не действует до запуска worker.
Файлы: server/actions/summary.ts:58–75; flashcard.ts:57–74;
lib/queue.ts:74–80,96–102; apps/worker/src/jobs/generate-summary.ts:36–44,
generate-flashcards.ts:43–51.
AIJob появляется при старте worker, а actions проверяют только DB AIJob.
Пока worker выключен/занят, повторные запросы ставят одинаковые задания.
BullMQ jobId не указан. Mock probe: два вызова реальной action → два success,
два queued jobs. Атомарно резервировать DB job до enqueue, использовать
стабильный jobId и transactional outbox. Это также уменьшит повторные расходы.

A16 [P2] Повторная доставка задания повторно вызывает AI и создаёт результаты.
Файл: apps/worker/src/jobs/generate-flashcards.ts:43–51,102–124;
generate-summary.ts:36–44. После DB commit и до BullMQ ack возможен crash.
Повтор выполняет pipeline заново. Probe одного payload дважды: aiCalls=2,
AIJob=2, FlashcardSet=2. Processor должен продолжать один durable job,
проверять completion и связывать результат уникально с job ID.

A17 [P2] Crash оставляет блокирующий AIJob PROCESSING без recovery.
Файлы: worker jobs generate-summary.ts:48–50;
generate-flashcards.ts:55–57; actions summary.ts:58.
Retry создаёт новую AIJob, старая PROCESSING остаётся. Проверка любой активной
записи блокирует будущую генерацию даже после успешного retry. Нужны один job
на delivery, lease/heartbeat и reconciliation зависших attempts.

A18 [P2] HTTP producers ждут Redis без конечного лимита.
Файл: apps/web/src/lib/queue.ts:17–18.
maxRetriesPerRequest:null вместе с offline queue подвешивает await queue.add.
Probe реального ioredis на закрытом localhost порту продолжал ожидание после
ошибок подключения; никаких Redis writes не выполнялось.
Отделить worker connections от HTTP producer; bounded retry/timeout и outbox.
Источник: https://docs.bullmq.io/guide/connections

A19 [P2] Ошибка enqueue парсинга скрывается как успешная загрузка.
Файл: apps/web/src/server/services/document.ts:65–72.
Документ уже сохранён, enqueue error только логируется, возвращается success.
Mock probe: ok=true, DB PENDING, задачи нет. Обещанного manual/cron retry
в проекте не найдено. Нужен outbox/reconciler или явная ошибка с работающим retry.

A20 [P2] S3 storageKey допускает перезапись разных документов.
Файлы: server/services/document.ts:30–32;
packages/db/prisma/schema.prisma:197.
Date.now + нормализованное имя совпадают для concurrent uploads в workspace.
Разные Unicode имена могут стать одинаковыми после очистки. Probe с fixed
clock: лекция.pdf и доклад.pdf → две DB rows, один S3 object, первый перезаписан.
Удаление первой записи удаляет объект второй. Использовать UUID/document ID
в key и unique storageKey constraint; filename оставить декоративным suffix.

A21 [P2] Ограничение10MiB применяется к файлу после чтения всего multipart.
Файл: app/api/workspaces/[workspaceId]/documents/upload/route.ts:54,62,71–76.
request.formData потребляет все части; дополнительные части игнорируются.
Probe реального route с mocked IO: file1byte + ignored11MiB → HTTP201,
body11,534,591bytes. Возможен memory exhaustion от больших/параллельных тел
запроса. Внешний production proxy/body limit неизвестен.
Нужен лимит общего тела, streaming parser с ограничением bytes/parts/files,
ранняя остановка; одной Content-Length проверки недостаточно.

A22 [P2] В приложении нет rate limits для входа и регистрации.
Файлы: lib/auth.ts:33–54; server/actions/auth.ts:21–47,58–88;
server/services/auth.ts:23–33.
Вход запускает bcrypt для существующих accounts; signup — bcrypt factor12
и DB transaction. Приложение не ограничивает частоту/квоты. Точная ошибка
existing email облегчает enumeration. Добавить IP/account limits, backoff,
signup abuse protection и нейтральные ответы. Наличие внешнего WAF неизвестно.

A23 [P2] Разрешённые длинные пароли bcrypt считает эквивалентными.
Файлы: packages/shared/src/schemas/auth.ts:8–9;
apps/web/src/server/services/auth.ts:33; lib/auth.ts:53.
Schema разрешает128characters, bcrypt использует72UTF-8bytes. Реальный probe:
hash72×a+A принимает72×a+B и один prefix. Unicode достигает лимита раньше.
Исправление: Argon2id или явно проверять UTF-8 byte limit; предусмотреть
миграцию существующих hashes. Источник: https://github.com/dcodeIO/bcrypt.js

A24 [P2] Удаление S3 и DB не имеет durable cleanup.
Файл: server/services/document.ts:92–99.
S3 error → DB row всё равно удаляется, объект остаётся без cleanup retry.
DB error после S3 delete → row ссылается на отсутствующий исходник.
Это source-level failure-path finding, реальные S3 сбои не имитировались.
Нужен tombstone/delete job/outbox и повторяемая cleanup операция.

7. AI и фоновые задачи

A25 [P2] Usage теряется на невалидном платном ответе; неизвестная цена равна0.
Файл: packages/ai/src/provider.ts:28–40,103–126,152;
worker generate-summary.ts:114–120, generate-flashcards.ts:140–146.
Validation выполняется до построения metadata. Parse/validation failure
теряет usage выполненного запроса; worker сохраняет только error, retry
порождает ещё один вызов. Для модели вне трёх exact names estimateCost=0;
snapshot alias probe также дал0 при ненулевых tokens.
Сохранять metadata каждой попытки до validation; неизвестную цену отображать
unknown/null, поддерживать модельные aliases и актуальный ценовой конфиг.
Реальные счета и актуальность численных тарифов таблицы не проверялись.

A26 [P2] AI output validation принимает бессодержательные результаты.
Файлы: packages/ai/src/prompts/summary.ts:91–122;
flashcard.ts:114–134. Приняты пробельные title/tldr/question/answer;
summary допускает пустые sections, а flashcards одну карточку вместо
обещанного количества. Неверные keyTerms silently фильтруются.
Нужны trim/min/max, строгие schemas и явный отказ от невалидного результата.

A27 [P3] BullMQ задания сохраняются бессрочно.
Файл: apps/web/src/lib/queue.ts:55–58,77–80,99–102.
removeOnComplete/removeOnFail не заданы; Redis хранит history без лимита.
Это постепенно расходует память. Задать retention age/count и наблюдать backlog.

8. Запуск, tooling и качество

A31 [P3] Format check ссылается на отсутствующий plugin.

A32 [P3] JWT onboarding flag доверяет клиентскому update payload.

A33 [P3] Некоторые обязательные поля допускают одни пробелы.

9. Риски, требующие отдельного подтверждения

• Markdown URL protocols не ограничены: components/assistant/markdown.tsx:61.
  engine.generateFileAnalysis интерполирует filename без escaping.
  Probe реального engine+renderer доказал javascript: href из crafted filename.
  XSS execution и доставка от внешнего атакующего не доказаны: attachment
  локален, link имеет target=_blank/noopener. Не приравнивать к A03.
  Экранировать filename, разрешать только безопасные URL schemes.
• Query helpers сами не требуют auth, но нынешние callers защищены.
  Это риск при расширении API, не доказанный текущий IDOR.
• Membership check и mutation разделены. При будущих move-resource/removal
  membership нужны атомарные predicates; соответствующих маршрутов сейчас нет.
• Реальные migrations на PostgreSQL, S3 permissions, Redis persistence,
  AI provider quality/latency, production proxy/TLS/headers/backups/monitoring
  и нагрузка не проверены. Нужен отдельный интеграционный прогон.
• Файлы .env.example и compose имеют dev credentials и явно описаны как
  local development. Это не доказательство использования этих секретов в prod.
