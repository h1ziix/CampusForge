## Состояния и клавиатура

- **Loading:** Documents list/detail и Flashcards list имеют именованный `role=status`, текст загрузки и `aria-busy`; декоративные skeletons скрыты от дерева доступности. Skeleton layout помещается в mobile shell. Spinners/skeletons отключают анимацию при reduced motion.
- **Empty:** понятные headings и действия Upload/Go to Documents; сохранённые sets больше не названы sample previews. Empty Study сообщает об отсутствии карточек и не показывает неработающие study controls.
- **Uploading / processing:** Upload имеет отдельное live сообщение; disabled controls не заменяют объявление статуса. Parsing и очередь генерации остаются polite status; Check status доступен с клавиатуры. Диалог сохраняет локальный вертикальный scroll.
- **Failed / uncertain:** ошибки upload — alert; ошибка извлечения — существующий polite status с причиной; FAILED/CANCELLED/UNCERTAIN генерации — alert. UNCERTAIN явно сообщает о возможном списании; проверка статуса не создаёт новую операцию. В тестах FAILED/UNCERTAIN после ручной проверки сохраняют ровно одну request/operation и не показывают успешный новый результат.

На **390×844, 768×900, 1024×900, 1440×900** пройден путь: empty Documents → Upload клавиатурой → выбранный длинный filename → сохранённый pending документ → processing → completed extraction → queued summary/cards → сохранённый результат → Study → раскрытие/скрытие → ссылка источника → Back to Documents. Проверяются Tab/Shift+Tab, Enter/Space, Escape, видимый focus, прокрутка и отсутствие горизонтального overflow. Ниже 768 используется mobile menu; начиная с 768 — видимый desktop sidebar. Отдельно проверены длинные имена, Summary вместе с каждым parsing state, разные controls вокруг Study, вложенные Escape и смена viewport.

## F05 и границы вывода

**F05 отложен в R3:** Assistant остаётся явно маркированным demo вне поддерживаемого пути Documents → результат → Study; его нет в основной workspace navigation. Изменения R1 сохранены. R3 не расширяет Assistant и не заявляет новую приёмку его composer. Это соответствует R2 и условию аудита F05.

Browser fixture копирует актуальные production shell/list/upload/detail/Study компоненты. Auth/session, upload acceptance, persistence, worker completion и AI output в новых R3 scenarios **явно синтетические**. Server Action RPC/React lifecycle исполняются в настоящем Next runtime. Эти проверки подтверждают UI и клавиатурные границы, **не** объединённый browser → настоящий auth/DB/S3/worker/provider E2E и **не** педагогическое качество AI. Семантические roles, names и focus проверены в Chromium; отдельный запуск реального screen reader не выполнялся. Реальные пользовательские документы, migrations и платный AI-провайдер в R3 не использовались.

R2 real-provider протокол остаётся невыполненным. F12 (сохранение учебного прогресса), эксплуатационный допуск/расходы/retention и другие находки вне R3 не объявляются закрытыми. Результат этапа не означает готовность платного пилота.
