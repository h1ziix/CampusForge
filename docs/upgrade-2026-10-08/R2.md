## Проверенный путь данных

1. **Upload:** route проверяет Origin, auth и membership; `readDocumentUpload` ограничивает multipart/body/headers, разрешает MIME и проверяет extension/bytes/UTF-8. `createDocument` создаёт durable upload intent, выполняет conditional S3 PUT и сохраняет document + PARSE outbox.
2. **Parse:** dispatcher/BullMQ передают durable obligation; worker с lease извлекает полный текст и сохраняет `parsedText`/processing state в PostgreSQL. PDF требует существующий текстовый слой; OCR нет.
3. **Admission:** generation action повторно проверяет auth/member и валидирует IDs/key. `requestGeneration` оценивает полные prompts; `requestAIOperation` блокирует workspace budget row, сохраняет immutable input/settings, reservation и AI outbox. Существующий key возвращает ту же operation; несовместимый input отклоняется.
4. **Worker → DB:** AI processor использует versioned prompts/attempt ledger, валидирует output и атомарно сохраняет `summaryJson` либо `FlashcardSet` вместе с terminal receipt. Неоднозначный provider outcome остаётся UNCERTAIN с удержанным резервом.
5. **DB → UI → Study:** scoped queries и `getDocumentGenerationStateAction` возвращают lean state. Результаты не реконструируются из filename/cache. Study использует существующую server page/query и настоящий `FlashcardViewer` для сохранённых cards.

Найдена дополнительная гонка: параллельные artifact/job SELECT могли вернуть `COMPLETED` уже после worker commit, но summary ещё из состояния до commit, остановив polling без результата. Регрессия воспроизвела это; теперь receipts читаются перед artifacts, а `hasSummary` согласован с возвращённым summary.

## Idempotency, ожидание и ошибки

- Неизменяемый uploaded document имеет одну UI logical operation на тип генерации. Ключ `doc-v1.<type>.<SHA-256([workspaceId, documentId, type])>` стабилен между повторными кликами, потерей ответа, tabs, membership users и reopen; browser storage не требуется. Синхронный lock препятствует повторной отправке до rerender. Серверная уникальность и проверка inputHash остаются окончательной защитой.
- Retry request после неподтверждённого admission использует тот же key. Ключ не меняется автоматически при ошибке или смене серверной policy: конфликт требует разбора, а не новой платной операции. Существующие active/terminal jobs и saved artifacts выключают новую генерацию на этом экране.
- UNCERTAIN явно сообщает о неизвестном результате и возможном списании. Ни status check, ни reopen, ни UI timer не запускают paid regeneration. FAILED/CANCELLED не выдаются за успех; ранее сохранённый результат, если существует, остаётся отдельно видимым.
- Автоматические read-only checks: **2, 4, 8, 16, 30, 30 секунд**, последовательно, без overlapping reads. Ручная проверка не возобновляет исчерпанный automatic budget. Read имеет deadline **15 секунд**, admission waiting — **30 секунд**. Deadline ограничивает ожидание клиента, не отменяет уже начатую серверную операцию. Поздний ответ после deadline/unmount/logout не подменяет состояние; повтор admission остаётся с прежним key.
- Успешная ручная проверка снимает устаревшую admission error после потерянного receipt. Проверка privacy lease сохранена; local sample caches игнорируются, новые source/results в browser storage не записываются.

## Реальные ограничения input

Upload: один файл, **10 MiB**, UTF-8 TXT/Markdown либо PDF с selectable text. DOCX, картинки, аудио и OCR не добавлены.

AI budget отдельный: текущий default **`AI_MAX_INPUT_TOKENS=16000`**, UI получает действующий серверный лимит. Admission считает консервативный upper bound **UTF-8 bytes обоих prompts + 128**, включая filename и instructions, а не точное число tokenizer tokens. Для каждого типа показана своя оценка. Лимита в страницах/символах не обещаем. Материал не обрезается молча; worker prompts получают весь immutable source. Input/output/attempt/spend ceilings не увеличивались ради успешного ответа.

## Границы интеграции и настоящий провайдер

Disposable integration использует fresh run-labelled PostgreSQL 16/Redis 7/MinIO, loopback ports, tmpfs и finally cleanup. Рабочие `.env`, пользовательская БД и пользовательские материалы не используются. Проверяются настоящие route handler (через Request), S3, Prisma transactions, BullMQ dispatcher/worker, admission actions и lean queries. Auth синтетический; worker исполняется in-process; AIProvider получает явно тестовый in-memory HTTP transport.

Подтверждены два разных источника с одинаковым filename и сохранением всех bytes до prompts; 20 параллельных запросов на одну logical operation; same-key replay и queue redelivery без нового AI call; чтение summary/jobs/Study новым Prisma connection; workspace scoping; Markdown empty MIME; oversized source с оценкой **33316 > 16000**, **0 новых operations/reservations/calls**; FAILED/UNCERTAIN без success artifacts и повторных paid requests. Всего **6 synthetic provider calls**, worker errors **0**. Контейнеры конкретного последнего run удалены и проверены по run label.

Это не объединённый browser → настоящий Next HTTP/auth → live DB → настоящий AI E2E и не оценка педагогического качества модели. Browser fixture использует копии актуальных production UI/hooks и Next Server Action RPC; реализации actions, persistence и provider внутри fixture синтетические.
