# CampusForge R2 — authentication, session updates и локальная приватность

Дата: **2026-10-05**, Asia/Qyzylorda. Изменения приложения реализованы в пределах R2. Этот отчёт различает исправление кода, application entrance на synthetic boundaries и live integration acceptance. **R2 не является разрешением на production.**

## Scope и исходное воспроизведение

Прочитаны переданные AGENTS-инструкции, независимый аудит, security domain report, R1 и README; отдельного AGENTS.md в checkout/проверенных предках нет. Работа разделена между auth/session, privacy/storage и независимым security regression review; root реализовал Markdown URL policy, upload Origin guard, environment contract и общий quality gate. Для UI применены frontend-senior, существующие компоненты/токены, Playwright и визуальная проверка. Redesign, document pipeline lifecycle и бизнес-изменения R3–R7 не выполнялись.

Старые probes адаптированы к **Next 16.3.8 / React 19.3.0 / NextAuth 5.0.0-beta.32**. [Source baseline](R2-evidence/baseline-source.json) исполняет актуальные TS modules с явно обозначенными mocks и реальным bcrypt: client update менял name/onboarding, password endpoints выполняли дорогие операции на каждую попытку, suffix после 72 bytes игнорировался. [Browser baseline](R2-evidence/baseline-runtime.json) использует original SignInForm и successful action fixture, **не реальную авторизацию**: Next 16 блокирует JavaScript marker с page error, но внешний callback меняет origin. React 19 заменяет `javascript:` href блокирующим sentinel, однако `data:` остаётся ссылкой. Старый XSS marker на Next 14 не объявляется воспроизведённым на R2 runtime. [Storage baseline](R2-evidence/baseline-storage.json) подтвердил загрузку общей legacy history через приложение.

Предварительные baseline browser запуски наследовали системный Node 20.20.0; это явно записано в evidence и не считается поддерживаемым R1 acceptance. Финальные проверки используют закреплённый **Node 24.21.0**, установленный вне проекта через `pnpm dlx node@24.21.0`; manifests/lock ради runtime не менялись.

## Security и privacy policies

Callback parser отвергает executable/opaque schemes, external origins, protocol-relative URLs, credentials в URL, backslashes, control/invisible characters и ambiguous/malformed encodings. Query/hash сохраняются только после успешной проверки. Навигационные sinks просмотрены через `rg`: остальные динамические routes строятся из server-generated scoped IDs или проверенных domain results; membership guards сохранены.

Password source budgets по умолчанию общие (`unknown`). IP partitioning разрешён только при explicit trusted ingress policy: origin недоступен напрямую, proxy удаляет клиентский header и записывает один проверенный IP. `AUTH_RATE_LIMIT_TRUST_PROXY`/`AUTH_RATE_LIMIT_IP_HEADER` передаются через Turbo. Requests расходуют общие source и endpoint/account budgets; rotating signup emails не обходят source limit. Lua обновляет counters атомарно, устанавливает TTL и не продлевает cooldown отказами. Timeout — 1500 ms, outage — fail closed с понятным retry. Direct Auth.js API сохраняет framework error code protocol; это не произвольный HTTP 429. Signup existing/new public response нейтрален; missing/wrong credentials выполняют один compare. Constant-time инфраструктура не заявляется.

Новый passwordHash содержит versioned policy marker и настоящий salted cost-12 bcrypt hash, без prehash/нормализации/обрезки. Marked hash не принимает дополнительные >72-byte suffixes. Raw legacy hashes до 512-byte input допускают прежнее сравнение; это покрывает все пароли старого signup (до 128 UTF-16 code units, максимум 384 UTF-8 bytes). Legacy suffix после 72 bytes всё ещё игнорируется. Ни schema migration, ни массового переписывания hashes нет. Imported credentials вне прежнего signup >512 bytes требуют отдельно спроектированного recovery flow; публичного reset endpoint в проекте нет.

Logout сначала отзывает локальные leases/таймеры/кеши, затем вызывает Auth.js. Удаляются только CampusForge sensitive assistant/document namespaces и legacy content keys; theme, scoped non-sensitive preferences и чужие origin keys сохраняются. Custom system prompt считается sensitive. Autosave=false немедленно удаляет sensitive persistence, сохраняя текущее in-memory состояние до навигации/logout. Legacy keys не импортируются. Cache не является шифрованием от DevTools/same-origin scripts. Недоступность одновременно storage и BroadcastChannel ограничивает межвкладочную доставку revocation; это отдельное browser limitation. При network logout failure данные остаются скрыты, доступен Retry sign out; local cleanup не выдаётся за доказанное удаление auth cookie.

Upload требует `Origin === new URL(AUTH_URL || NEXTAUTH_URL).origin`, отсутствие/`null`/чужой origin отклоняется; `sec-fetch-site`, если присутствует, должен быть `same-origin`. Host/forwarded headers не выбирают trusted origin. Multipart/S3/DB/queue lifecycle сохранён. Отсутствие прежнего Origin guard было **conditional same-site threat**, а не доказанным универсальным cross-site CSRF: SameSite=Lax обычно ограничивает cookie отправку. Auth.js CSRF и Next Server Actions Origin guard проверяются отдельно. [Next Origin policy](https://nextjs.org/docs/app/api-reference/config/next-config-js/serverActions), [Auth.js CSRF error contract](https://authjs.dev/reference/core/errors), [React JavaScript URL protection](https://react.dev/errors/323) соответствуют наблюдаемому runtime, но не заменяют tests.

## Фактические проверки

Итоговый sequential gate: `pnpm verify:r2`. Он очищает inherited runtime secrets из child env, задаёт исключительно synthetic DATABASE_URL, выполняет generation/validation, все packages typecheck/lint, format check, tests, Turbo env probe, build и smoke actual compiled middleware/session. Ни одна команда не выполняет migration или подключение к пользовательской БД.

Результаты команд и timings: [quality-results.json](R2-evidence/quality-results.json). `pnpm verify:r2` завершился exit 1 исключительно из-за formatting двух последних fixture type repairs; сами tests/build/smoke прошли. Эти два файла отформатированы отдельно, повторный `pnpm format:check` завершился exit 0. Исходный failure сохранён, итоговое состояние checks отмечено отдельно; scripted run не переименован в exit 0 задним числом.

## Непроверенные integration cases и оставшиеся блокеры

- Docker daemon недоступен (`DockerDesktopLinuxEngine` pipe отсутствует); native redis-server не найден. Disposable PostgreSQL/Redis не provisioned. Не проверены DB-backed real signup/login/logout, full two-user/two-workspace membership flow, existing-account recovery и реальные transaction races.
- Redis Lua execution, реальный atomic parallel counter на разных app instances, actual TTL expiry/restart/Cluster и outage→live recovery не подтверждены JS shim/cooldown controls. Они обязательны до production admission. Actual ioredis на закрытом synthetic localhost подтверждает только bounded fail-closed transport failure.
- Synthetic JWT cookie middleware smoke подтверждает route/matcher/Edge-compatible decode и Node session agreement, **не credentials authentication**. Production reverse proxy/header stripping, HTTPS Secure/SameSite cookie topology, WAF и session revocation deployment policy не предоставлены.
- Existing FE-01 composer clipping/overflow и другие R3–R7 findings не исправлялись в R2. Screenshot observations отделены от новых auth/privacy states. S3 multipart budgets, queue durability, parser/content safety и real AI остаются вне scope.
- Пользовательские данные, настоящая `.env`, существующая DB schema/hashes не изменялись; paid AI, Git commit/push, deployment не выполнялись. Прежние audit/R1 evidence проверяются отдельной hash-сверкой.
