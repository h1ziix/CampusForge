# R2 — independent security regression review

Date: 5 October 2026. This review covers the R2 application changes and their evidence. It is not production authorization.

## Current runtime baseline

The baseline was captured before authentication/storage fixes on installed Next **16.3.8**, React/ReactDOM **19.3.0**, NextAuth **5.0.0-beta.32**. Initial probe commands used the host's Node **20.20.0**; final regression commands explicitly use supported Node **24.21.0**. The old audit's browser JavaScript marker result must not be reused as a current-runtime result.

- The original `SignInForm` passed the query callback directly to `router.push`. In the current Next runtime, `javascript:` was blocked with a security error and the synthetic marker remained absent. An external HTTPS callback still changed browser origin after an explicitly mocked successful login. The external destination was intercepted by Playwright; no external service was contacted. A normal `/dashboard` callback worked.
- React 19 replaced the original Markdown JavaScript href with its throwing security sentinel. The original `data:` href remained present. Raw HTML was escaped. Thus the previous React 18 JavaScript href observation is not the current React 19 outcome.
- The original assistant read synthetic user A content from the common `campusforge:assistant:v1` key in the actual browser fixture. Source probes also confirmed untrusted JWT name/onboarding updates, twelve unrestricted credential lookup/compare calls, twelve signup hashes, and real bcrypt suffix equivalence beyond 72 UTF-8 bytes.

Evidence: [baseline runtime](R2-evidence/baseline-runtime.json), [baseline assistant browser result](R2-evidence/baseline-storage.json), [baseline source probes](R2-evidence/baseline-source.json). The archived baseline source probe is a pre-fix observation, not a final regression command. No past audit or R1 evidence was changed.

## Actual application entrances exercised

`scripts/next-runtime-fixture.mjs` copies the actual application components, Node authentication/provider/callbacks, Server Actions, auth service, middleware module and upload Route Handler into a disposable Next application. It never copies `.env`. The fixture has these explicit boundaries:

| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Callback UI               | `SignInForm`, `safePostLoginPath`, Next App Router, React                                                                                  | The `/sign-in` action returns delayed synthetic success/error; this is not real authentication.                                                                                                                                                 |
| Credentials/session/CSRF  | Installed NextAuth handlers and actual application Node auth callbacks/provider                                                            | In-memory Prisma rows and Redis transport/eval semantics; no real database or Redis. Seed users use low-cost synthetic bcrypt hashes, so this fixture does not prove timing equalization. Actual new signup still hashes at cost 12.            |
| Password action entrances | Actual `signInAction`, `signUpAction`, `completeOnboardingAction`, auth service                                                            | Same synthetic infrastructure; real bcrypt plus observable counters.                                                                                                                                                                            |
| Onboarding success UI     | Actual `OnboardingForm` with its action import pointed to the copied actual action; actual SessionProvider `update({})` and cookie refresh | Synthetic user's profile is written only to in-memory Prisma. The form reaches dashboard and actual session claims match the written profile.                                                                                                   |
| Middleware compatibility  | Copied actual middleware with real encrypted Auth.js cookies                                                                               | Invoked by a Node Route Handler using a synthetic target URL. Its `NextResponse.next` result is exposed by a documented harness adapter. This is not an Edge matcher/deployment test; the separate production runtime smoke owns that evidence. |
| Upload                    | Actual upload Route Handler, configured-origin guard, multipart parsing, authentication and membership checks                              | The final `createDocument` boundary records a synthetic success; S3, actual DB and queues are not exercised.                                                                                                                                    |

The Redis shim does not execute Lua, run multiple instances or prove real TTL behavior. Its explicit cooldown control clears synthetic counters. Real Redis atomicity, TTL, recovery and concurrency remain integration acceptance work.

## Regression results and review conclusions

The standalone feature run completed **15/15 browser tests** on Node 24.21.0. After the visual contrast polish and keyboard-focus refinement, the full release gate completed **20/20 browser tests**, including all five R1 regressions, with no skips or flaky cases. Authoritative final results are [browser-results.json](R2-evidence/browser-results.json); the standalone feature log is [browser-final-feature.log](R2-evidence/browser-final-feature.log).

The independent production smoke additionally completed **9/9 checks** against the actual compiled Next server and original middleware matcher: anonymous routes, malformed cookie, onboarding redirects/render, signed-in auth page, and Node session agreement with the Edge-compatible cookie. [Production middleware evidence](R2-evidence/production-middleware.json) uses signed synthetic JWT cookies and does not perform credentials authentication or DB queries. R1's middleware deprecation, Next/jose Edge import traces and Node module-inference build warnings remain visible in the build log; the successful smoke does not certify every deployment's Edge runtime.

- Ten crafted callbacks, including schemes, external origin, protocol-relative, backslash, encoded ambiguity and control characters, reach a safe same-origin fallback without a marker or browser security error. A legitimate local query/hash route works. This proves the actual component entrance under fixture login; live disposable-DB login remains unverified.
- The browser A/ws1 → A/ws2 → logout → B/ws1 sequence isolates conversations, attachment previews and drafts. Reload/back, a second tab, blocked storage, disabled autosave and ownerless legacy content were exercised. Logout leaves unrelated origin data and the non-sensitive theme preference intact. Existing timers cannot rewrite content into a new identity's namespace.
- Twelve concurrent direct credential requests with spoofed forwarding headers permit ten expensive lookup/compare operations. The actual Server Action cannot bypass the same account budget. Different signup emails exhaust the shared five-signup source budget; subsequent requests perform no hash/write. Synthetic Redis outage denies both API and action entrances and operation recovers afterward.
- New signup's marked strict bcrypt hash accepts the 72-byte password and rejects a longer suffix at the actual credentials endpoint. A raw legacy synthetic hash retains historical suffix compatibility. Unit/integration probes cover ASCII/Unicode 71/72/73-byte boundaries. No existing user row was changed or silently rehashed.
- Actual session update requests with attacker id/role/onboarding/name, oversized strings, arrays and null do not change trusted claims without a DB write. Malformed JSON fails safely. Session cookie output stays below 5,000 characters in the exercised cases. A legitimate onboarding write refreshes claims and opens dashboard through the actual form.
- Auth.js missing-CSRF credentials, session and signout requests fail; the existing session survives a forged signout. A captured actual Next Server Action replay with a sibling origin is rejected before additional expensive work. The custom upload rejects missing/null/cross-origin/same-site Origin before auth/multipart work; anonymous and foreign-workspace requests are also denied. A same-origin synthetic multipart request reaches the mocked final upload boundary.
- Markdown dangerous URLs render as text, raw HTML remains escaped, external links retain `noopener noreferrer`, and the safe local link opens its intended same-origin destination.

CSRF evidence is conditional on cookie and ingress configuration. A sibling-site browser threat differs from a cross-site request; do not claim a demonstrated production exploit from source inspection. The trusted proxy must strip attacker-supplied forwarding headers. Neither configured upload Origin nor password source identity trusts an arbitrary request Host/X-Forwarded-For.

## Browser visual review

The matrix covers **390, 768, 1024 and 1440 pixels**, each in light/dark. It exercises sign-in, signup, onboarding and local-session-cleared UI, keyboard focus, pending/disabled submit, visible errors, logout network failure and retry. Screenshots and [ui-matrix.json](R2-evidence/ui-matrix.json) are saved beside the machine-readable test result. All eight combinations report no horizontal overflow or page errors. Actual source components were inspected; newly introduced logout error text and touched authentication alerts received a contrast polish pass using the semantic `error-foreground` token. The final 390px dark error, 1440px light keyboard-focus, 1440px dark sign-in error and 390px light onboarding error screenshots were visually reviewed after the gate: text is readable, error wrapping is contained and the keyboard ring is visible. Fixture headings/identity controls are labelled test tooling, not production interface changes.

The previously audited assistant welcome/composer clipping remains **FE-01**, outside R2's explicit security scope. No redesign or R3–R7 business change was performed. Horizontal overflow checks pass; this does not assert that unrelated frontend findings are resolved.

## Remaining acceptance boundaries

Docker Desktop's Linux engine is unavailable and no native Redis server was found. A real disposable PostgreSQL/Redis auth stack was not provisioned. Therefore live DB authorization/login, real Redis Lua/TTL/multiple-instance behavior, exact production ingress/source enforcement and infrastructure outage recovery remain unverified. No existing `.env`, user database, migrations, paid AI calls, Git commits/pushes or deployment were used. The findings must not be declared fully closed solely from this synthetic evidence.
